# Pilot run — a legacy estate through the whole path / 레거시 자산 전 구간 통과

> **Measured 2026-08-14** by `spikes/estate/run.sh` over `spikes/estate/idl/`,
> thirteen IDL files written for this run. Every number below came out of that
> script; re-run it with `--tsv` for the rows alone.
> **2026-08-14 측정.** 아래 수치는 전부 그 스크립트의 출력이다.

Four separate limits in this project say, in effect, *"a pilot closes this."*
Every measurement until now ran over contracts **we** wrote, one at a time, on
loopback, against fixtures we start. This is the first time a **set** shaped
like a deployment — many interfaces, inconsistent naming, inherited hierarchies,
`#pragma prefix` on some files and not others, and two contracts that would
embarrass their author — has been pushed through ingestion, registration,
generation, exposure and an agent call all at once.

이 프로젝트의 한계 네 건이 사실상 *"파일럿이 닫는다"*고 적혀 있다. 지금까지의
모든 측정은 **우리가 쓴** 계약을 한 건씩 돌린 것이었다. 배포 형태의 **집합**이
수집·등록·생성·노출·에이전트 호출을 한 번에 통과한 것은 이번이 처음이다.

**The headline is not the pass.** The path completes end to end. What it
produced is a measurement nobody could have taken with one file: **76 of 76
operations across twelve interfaces would be ALLOWED to an agent holding no
scopes at all**, because the guard's two content gates key on annotations that
legacy IDL does not have. That is §4 below, and it is what this batch exists to
produce.

**중요한 것은 통과가 아니다.** 경로는 끝까지 완주한다. 그러나 파일 하나로는
결코 얻을 수 없는 측정이 나왔다 — **인터페이스 12개, 연산 76개 전부가 스코프를
하나도 갖지 않은 에이전트에게 허용된다.** 가드의 내용 게이트 두 개가 레거시
IDL에는 없는 애너테이션에 키를 걸기 때문이다.

## 1. The estate / 자산의 형태

Thirteen files, `spikes/estate/idl/`, written against the OMG grammar. **Not in
`corpus/`, on purpose** — the corpus is a gate's fixture set and this is a
consumer. Nothing here is a fixture for anything.

| file | what it contributes |
|---|---|
| `01-common.idl` | the shared file everyone includes: `ISODate` (a string, with the apology in a comment), `RecordId`, `StringList`, `AuditStamp`, two exceptions, and `Describable`, the base ten of twelve interfaces inherit |
| `02-mfs-types.idl` | **reopens `MFS::Common`** from another file: `BlobData`, `Priority`, `Amount`, a union |
| `03-booking.idl` | the oldest module; four operations, two user exceptions |
| `04-shipment.idl` | **eleven operations** on one interface, because every team that wanted a tracking feature added it here |
| `05-billing.idl` | **no `#pragma prefix` at all** — the pragma stayed behind when the file was split out in 2006 |
| `06-customer.idl` | the prefix written **inside `module MFS`**, not at file scope |
| `07-legacy-edi.idl` | the embarrassing one: `doIt` with nine parameters, Hungarian names, an `any` payload, an `inout` correlation id, three `out` params, and a screaming second entry point nobody migrated to |
| `08-depot-codes.idl` | one typedef and a constant in their own file, because a generator that was turned off in 2015 used to write it |
| `09-warehouse.idl` | **only compiles because of a typedef three files away**: includes 08 and nothing else, uses `ISODate`, `AuditStamp` and `Priority` from 01 and 02 through `08 → 02 → 01` |
| `10-dispatch.idl` | the deepest chain: `Dispatcher : Routable : Describable` |
| `11-pricing.idl` | an acquired company's file — **a different prefix** (`trans-continental.example`), its own module, inheriting our base interface |
| `12-audit.idl` | the only writable attribute and the only `oneway` in the estate |
| `13-admin.idl` | the second embarrassing one: flat module, `SHUTDOWN(in string reason, in boolean bForce)`, ALL-CAPS names, **no exceptions anywhere** — a failure returns `FALSE` |

52 declared operations; 76 once inherited operations and attribute accessors are
resolved. 49 repository ids. 12 exposable interfaces.

파일 13개, 선언 연산 52개(상속·속성 접근자 해석 후 76개), 리포지터리 ID 49개,
노출 가능 인터페이스 12개. **`corpus/`에 넣지 않았다** — 코퍼스는 게이트의
픽스처 집합이고 이것은 소비자다.

## 2. Per-stage first-pass rates and the round count / 단계별 1차 통과율과 라운드 수

Batch size **13**. Rounds **2**. The two numbers measure different things and
are stated separately, per the operating model.

| stage | what ran | first pass | after repair |
|---|---|---:|---:|
| 1 — S4 per file, as stored | `sidl-validate <file>` × 13 | **2/13 (15%)** | 2/13 — **unrepairable in this footprint** |
| 2 — the oracle per file | `omniidl -b dump <file>` × 13 | **7/13 (54%)** | **13/13 (100%)** |
| 3 — one translation unit | `sidl-validate` on the splice | 1/1, 104 advice | — |
| 4 — identity vs omniidl | `repository-ids` vs `omniidl -bpython` | **44/49** | **49/49** |
| 5 — S4 gate + S5 register | `forge-pipeline --only s4 --register` | 1/1, 12 exposable | — |
| 6 — both generated halves | `gen-corpus` | **12/12 interfaces, 0 skips** | — |
| 7 — dry run | `orbweaver-mcp-server --dry-run` | 76/76 answered | — |
| 8 — served | hand-written servant on our POA | 1/1 | — |
| 9 — agent call | two sessions through the bridge | 2/2 | — |

Stage 1's 15% is a measurement **of the front end**, not of the estate: the
oracle accepts all thirteen of the same files. Stage 1 cannot be repaired here
because the repair is a `crates/` change (RC-1).

1단계의 15%는 자산이 아니라 **프런트엔드**에 대한 측정이다 — 같은 13개 파일을
오라클은 전부 받아들인다. 수정이 `crates/` 변경이므로 이 배치에서는 고치지
않는다.

## 3. Root causes, clustered / 근본원인 (항목이 아니라 원인 단위)

Eight causes. Two were ours and were repaired and codified; six are findings
about the project and are reported rather than made, because the footprint of
this batch excludes `crates/`.

### RC-1 — `#include` is skipped, not resolved · 11 of 13 files · **crate finding**

`crates/orbweaver-idl/src/lex.rs` skips `#include` along with every other `#`
directive. Every file of the estate that names a type declared in another file
therefore fails semantic analysis on its own — 11 of 13, with 90 diagnostics,
all of them `unknown-name`. The same 13 files are accepted by `omniidl`, which
runs a preprocessor.

This is the difference between a corpus and an estate. Every fixture in
`corpus/` is a single self-contained file, so no corpus case can ever exercise a
cross-file reference, and the gap is invisible at corpus scale by construction.

**What the path needs:** `#include` resolution with an include path, or a
documented multi-file entry point that takes a set of files and one scope. Until
then the only multi-file story is textual concatenation, which is RC-4.

`#include`가 해석되지 않고 건너뛰어진다 — 13개 중 11개 실패, 진단 90건 전부
`unknown-name`. 같은 파일을 omniidl은 전부 받는다. **코퍼스의 모든 픽스처가
단일 파일이므로 이 결함은 코퍼스 규모에서는 구조적으로 보이지 않는다.**

### RC-2 — the fix hint for a fully-qualified name is corrupted · ~90 diagnostics · **crate finding**

Every diagnostic about a `::`-qualified name prints the wrong name in its own
fix hint:

```
error: "::MFS::Common::StringList" is not declared [unknown-name]
    fix: "::" is not declared anywhere in scope. Declare it, qualify it with
         its module (`Module::::`), or correct the spelling.
```

The error line is right and the hint is wrong: it has split the scoped name on
`::` and taken an empty leading segment as the missing identifier, then
suggested qualifying `::` with `Module::::`. Unqualified names in the same run
produce correct hints (`"AuditStamp" is not declared … qualify it with
`Module::AuditStamp``), so the bug is specific to the leading-`::` form.

This matters more than a cosmetic message bug because of what CLAUDE.md claims
for this gate: *"it catches this class with an actionable message."* At estate
scale the actionable half is wrong on the majority of diagnostics, and it is
wrong in the direction that wastes the reader's time — it names a token that is
not the problem.

`::` 정규화 이름에 대한 수정 힌트가 손상되어 있다. 오류 줄은 맞고 힌트만 틀리며,
비정규화 이름에서는 정상이다. 게이트의 가치가 "실행 가능한 메시지"에 있다고
적혀 있는 만큼, 진단 대다수에서 그 절반이 틀린 것은 미용 문제가 아니다.

### RC-3 — no include guards · 6 of 13 files · **ours, repaired and codified**

The estate as first written had no `#ifndef` guards. Files including both
`01-common.idl` and `02-mfs-types.idl` double-included 01 through 02, and
`omniidl` rejected six of thirteen with *"Declaration of typedef declarator
'ISODate' clashes with earlier declaration."*

Repaired across the whole set in one pass: every file carries a guard.
Round 2 measured 13/13.

**The finding underneath the repair:** our front end could not detect this class
at all, and structurally cannot, because it never processes an `#include`. The
defect was found only by the oracle. A project that relied on `sidl-validate`
alone would ship a double-including estate and discover it at the peer.

인클루드 가드가 없었다(13개 중 6개가 오라클에서 거부). 전체 집합에 한 번에
수정을 적용했고 라운드 2에서 13/13. **수정 아래의 발견**: 우리 프런트엔드는
`#include`를 처리하지 않으므로 이 부류를 구조적으로 탐지할 수 없다. 오라클만이
잡았다.

### RC-4 — a file-scope `#pragma prefix` leaks across a splice · 5 ids · **ours, repaired and codified — but it is a project finding too**

This is the one the coordinator asked to be stated plainly, so here it is
plainly.

A file-scope `#pragma prefix` is in force **to the end of its file**. After the
thirteen files are concatenated into one translation unit there is only one
file, so a prefix set by the file at line 200 is still in force when the
declarations of the file at line 400 arrive. `05-billing.idl` carries no prefix
of its own — that is the point of the file — and it follows `04-shipment.idl`,
which sets `meridian.com`. Measured, with `amalgamate.py --naive`:

```
omniidl, files compiled separately    the naive splice
IDL:MFS/Billing/InvoiceService:1.0    IDL:meridian.com/MFS/Billing/InvoiceService:1.0
IDL:MFS/Billing/Invoice:1.0           IDL:meridian.com/MFS/Billing/Invoice:1.0
IDL:MFS/Billing/LineItem:1.0          IDL:meridian.com/MFS/Billing/LineItem:1.0
IDL:MFS/Billing/LineItems:1.0         IDL:meridian.com/MFS/Billing/LineItems:1.0
IDL:MFS/Billing/AlreadySettled:1.0    IDL:meridian.com/MFS/Billing/AlreadySettled:1.0
```

**How a reader would have noticed: they would not have.** That is the whole
problem. Both columns are well-formed repository ids for plausible modules.
Nothing errors, nothing warns, the splice compiles, S4 passes 1/1, S5 registers
it, the catalog lists it, and `gen-corpus` emits stubs. The only thing that ever
disagrees is a peer — at which point `_is_a` returns false, the IOR's `type_id`
does not match, and the guard's `--expose IDL:meridian.com/MFS/Billing/InvoiceService:1.0`
allowlists an interface that no deployed object has. **The refusal an operator
then sees is indistinguishable from a permissions misconfiguration**, which is
exactly the failure mode D005 recorded for the scope vocabulary gap, arriving
here by a different road.

It is a finding about the project and not only about this driver. **Any consumer
that puts declarations from two files into one scope inherits it**: this
`amalgamate.py`, any hand-written "cat the estate together" step an operator
writes for the same reason (RC-1 leaves no other option), and any future
multi-file front-end entry point that concatenates rather than compiling each
file in its own prefix context. The rule that makes it safe is one line — *each
file begins with the empty prefix* — and nothing in the tree states it, because
until a set of files existed there was nowhere for it to be stated.

**Repaired:** `amalgamate.py` emits `#pragma prefix ""` before each spliced
file's own body, which is the state that file would have begun in had it been
compiled alone. **Codified:** stage 4 of the driver diffs both splices against
`omniidl` on every run — the reset splice must agree exactly, and the naive
splice must still drift, so the assertion cannot quietly become vacuous.

파일 스코프 `#pragma prefix`는 **그 파일 끝까지** 유효하다. 이어 붙이면 파일이
하나뿐이므로, 앞 파일의 프리픽스가 뒤 파일의 선언까지 따라온다. 접두사가 없는
`05-billing.idl`의 ID 5개가 `meridian.com/`을 얻었다. **독자가 알아챌 방법은
없다** — 양쪽 다 정상적인 리포지터리 ID이고, 오류도 경고도 없으며, S4·S5·생성이
모두 통과한다. 불일치는 오직 피어에서만 드러나고, 그때의 거부는 권한 설정
오류와 구분되지 않는다. **파일 두 개의 선언을 한 스코프에 넣는 모든 소비자가
이것을 물려받는다.** 수정: 각 파일 본문 앞에 `#pragma prefix ""`. 성문화: 드라이버
4단계가 매 실행마다 두 splice를 omniidl과 대조한다.

### RC-5 — an unannotated contract disables both content gates · 76 of 76 operations · **crate finding, and the headline**

`--expose` every registered interface, `--as ops-agent`, **no `--scope` at all**:

```
interfaces=12 operations=76 allow=76
allowed, among them: AuditSink._set_enabled, AuditSink.purge,
  EdiGateway.flush_queue, InvoiceService.void_invoice,
  ShipmentTracker.cancel, SystemConsole.SHUTDOWN
```

Nothing is refused. `SystemConsole.SHUTDOWN` — the operation that takes a force
flag — is `allow`. `AuditSink._set_enabled`, which turns the audit log off, is
`allow`. `AuditSink.purge`, which deletes its history, is `allow`.

The mechanism, read out of `crates/orbweaver-mcp/src/policy.rs`:

```rust
let effect = annotations.get("ai_effect")?;   // None -> no approval required
match effect.trim() {
    "read_only" | "readonly" | "idempotent" | "safe" => None,
    other => Some(other.to_owned()),          // unrecognised -> approval required
}
```

A **misspelled** `ai_effect` needs approval; a **missing** one does not. The
safe-direction rule is applied to a typo and not to an absence. `required_scopes`
behaves the same way, so a caller with no scopes satisfies every operation.

Two things make this a finding rather than a known limit:

1. **`COMPONENTS.md` already states this hole — for *ingested* contracts.**
   Row `orbweaver-registry`: *"ingested entries carry no SIDL, so the guard's
   `ai_effect`/`ai_authz` gates have nothing to key on — a second, independent
   reason exposure stays off."* It is framed as a property of remote IFR
   ingestion. It is a property of **any unannotated contract**, which is every
   IDL file on every legacy disk, whether it arrived over the wire or was read
   from `.idl`. The document names the narrow case and the broad case is the
   same case.

2. **`sidl-validate` tells the operator the opposite of what the bridge does.**
   The S4 advice on all 52 operations reads: *"has no `ai_effect`, so the bridge
   must assume it needs approval."* The bridge does not assume that. Measured:
   it allows. This is advice and does not gate — correctly, a gate that blocks
   on advice is one people route around — but it is the sentence the person
   doing exactly this migration will read 52 times, and it is false.

**What the path needs, stated as a choice rather than a patch:** either a
missing `ai_effect` refuses like an unrecognised one (which turns exposure of
any legacy estate into 76 approvals and would be routed around), or the bridge
grows a per-exposure default effect an operator sets once, or the advice text is
corrected to say what actually happens. All three are `crates/` changes. The
third is a one-line change and is the *least* useful, but it is the one that
stops the tool from misinforming the person it is talking to.

애너테이션 없는 계약은 승인 게이트와 스코프 게이트를 둘 다 무력화한다 — 76/76
허용, `SHUTDOWN`·`purge`·`_set_enabled` 포함. **오타난** `ai_effect`는 승인을
요구하고 **없는** `ai_effect`는 요구하지 않는다. `COMPONENTS.md`는 이 구멍을
*원격 수집* 계약의 속성으로 적어 두었으나, 실제로는 **모든 미주석 계약**의
속성이다. 그리고 `sidl-validate`는 "브릿지가 승인을 요구할 것"이라고 52번
조언하는데, 브릿지는 그러지 않는다.

### RC-6 — `.sidl.idl` is the only filename S4 discovers · 1 of 1 · **crate finding**

`forge-pipeline --only s4` resolves its work through `input_stage(Validate) =
Annotate`, whose artifact suffix is `.sidl.idl`. A legacy contract that no
annotation stage has ever seen is therefore invisible to the gate:

```
$ forge-pipeline --out <dir> --only s4 --register     # with ESTATE.idl present
nothing to run: no item has an input artifact for S4 validate
```

The workaround is to name the file `.sidl.idl`, and doing so makes the
pipeline's own honesty line report the opposite of the truth:

```
S4 gated 1 annotated file(s) and 0 unannotated draft(s)
```

That line exists precisely because *"S4 passed" says something different about a
file no annotation stage has seen* — the crate says so in a comment. At estate
scale the line reports the **filename**, and the filename is forced.

레거시 계약을 S4에 넣는 유일한 방법은 `.sidl.idl`로 이름 짓는 것이고, 그렇게
하면 파이프라인의 정직성 문구가 "주석된 파일 1건"이라고 거짓을 보고한다.

### RC-7 — the generated module name carries the pipeline-stage suffix · 1 · **crate finding, minor**

`gen-corpus` derives its module name from the file stem, so generating from
`ESTATE.sidl.idl` emits `f_ESTATE_sidl`. Combined with RC-6 — where `.sidl.idl`
is the only name the gate accepts — the two tools disagree about what a legacy
contract's filename means, and the driver has to keep two copies of identical
bytes under two names to satisfy both.

### RC-8 — `describe_interface` omits inherited operations · 10 of 12 interfaces inherit · **crate finding**

Three views of `ShipmentTracker`, measured in one run against one live object:

| view | operations |
|---|---:|
| `describe_interface` — what the **agent** reads | **11** |
| `--dry-run` — what the **guard** would judge | **13** |
| the wire — what the **servant** answers | **13** |

The two missing ones are `describe` and `_get_label`, inherited from
`Describable`. The agent invoked `describe` successfully in the same session in
which its own description of the interface did not list it. So an agent cannot
discover an inherited operation, can call one, and the guard is gating
operations the agent was never shown.

Ten of twelve interfaces in this estate inherit `Describable`; one inherits two
levels. On a single-interface contract with no base this is invisible, which is
why it has not been found before.

한 객체에 대한 세 관점이 어긋난다 — 에이전트가 읽는 `describe_interface`는 11개,
가드의 dry-run은 13개, 서번트는 13개를 답한다. 에이전트는 상속 연산을 **발견할
수 없지만 호출할 수는 있다.** 12개 중 10개가 `Describable`을 상속하는 자산에서만
보이는 결함이다.

## 4. Ergonomics at this size — the gate that is correct and unusable / 규모에서의 사용성

The batch was asked to find *a gate that is technically correct and unusable at
this size.* It found one, and it is not the one that was expected.

**The exposure allowlist is usable and the guard's per-operation model is
usable.** `--expose <interface>.<operation>` works, the refusal names the stage
(`authz.exposure`), and a refusal for an operation that does not exist is
byte-identical to one for an operation that does — measured in session B, so a
refusal is not an enumeration oracle. Twenty-four arguments for twelve
interfaces is fine.

**What is unusable is the dry-run report on an unannotated estate.** 7,253 bytes
of JSON, 76 operation entries, every single one `"would": "allow"`, and a
summary reading `allow=76`. An operator signing off an exposure reads a document
whose entire content is the word `allow` seventy-six times. It is *correct* —
that is genuinely what the gate would do — and it carries no signal at all,
because the answer does not vary. The instrument is designed to show an operator
which operations differ from the default and why; on the input that most needs
review it shows that nothing differs from anything.

The comparison that makes the point: on the annotated single-contract path
(`spikes/end_to_end.sh`), the same report reads
`allow=2 need_scope=1 need_approval=0` — three operations and one of them stands
out. Scale to seventy-six operations *and* remove the annotations, which is what
a real estate does, and the signal goes to zero at exactly the moment the
document gets long enough that nobody reads all of it.

노출 허용목록과 연산 단위 모델은 **쓸 만하다** — 거부가 단계를 명시하고, 존재하지
않는 연산의 거부와 존재하는 연산의 거부가 구분되지 않는다(열거 오라클이 아니다).
**쓸 수 없는 것은 미주석 자산에 대한 dry-run 보고서다** — JSON 7,253바이트,
항목 76개, 전부 `allow`. 정확하지만 신호가 0이다. 답이 변하지 않기 때문이다.

## 5. What worked exactly as intended / 의도대로 동작한 것

A pilot report that lists only problems misrepresents the system as much as one
that lists none. These were measured, not assumed.

- **`#pragma prefix` identity holds at estate scale.** Once the splice resets
  the prefix per file, **49 of 49 repository ids match `omniidl` exactly** —
  across a file-scope prefix, a prefix written inside a module, an acquired
  company's different prefix, a file with no prefix at all, and inheritance
  across all four. The pragma work was done against sixteen single-file corpus
  cases; it survives a thirteen-file estate unchanged.
- **The prefix-inside-a-module case caught a wrong belief in the estate itself.**
  `06-customer.idl`'s comment claims the pragma's placement "happens to produce
  the same ids." It does not: the ids are `IDL:meridian.com/Customer/...`, with
  `MFS` dropped. Both compilers agree it is dropped. The tools were right and
  the file's author was wrong, which is what an oracle is for.
- **S5 default-deny.** 12 exposable interfaces, 12 `exposed=no`, no exceptions,
  no way to be exposed by having been registered.
- **Generation over an estate: 0 skips, 50 items, 12/12 interfaces with both
  halves.** Including an `any` payload, a union with a `default`, a `oneway`, a
  writable attribute, three levels of inheritance, nine-parameter operations
  with `inout` and three `out`s, and sequences of structs. 8,384 lines.
- **A hand-written servant compiles against a generated trait for a contract
  nobody wrote for us**, in a crate outside the workspace, so it stands on the
  published crate surface alone. `knows()` had no default and had to be
  answered; the two user exceptions round-tripped as content.
- **The generated skeleton dispatches an inherited operation.** `describe` comes
  from `Describable` and is never declared on `ShipmentTracker`; the skeleton
  resolves the chain and serves it. (That the *description* omits it is RC-8 —
  the skeleton half is right.)
- **The dry run made no call and left a complete record.** 76 questions, 76
  audit lines, every one under its own `DRYRUN-` token, nothing dialled, at an
  instant when nothing was listening.
- **Default-deny search.** With one interface exposed, `search_interfaces`
  returned exactly one of twelve. The other eleven were registered, catalogued,
  and invisible.
- **No endpoint reached the agent.** No stringified IOR in any frame; the root
  handle went to stderr, where it is not a protocol frame.
- **The session survives a refusal** and keeps answering, in both sessions.
- **`omniidl` as an external program only.** The oracle is invoked and its text
  output read — clause (b) of the licensing boundary. Nothing is imported,
  linked or vendored, and the estate is original work written against the OMG
  grammar.

파일럿 보고서가 문제만 나열하면 문제가 하나도 없다고 하는 것만큼 시스템을
왜곡한다. 위 항목은 전부 측정된 것이다 — 특히 **리포지터리 ID 49/49가 omniidl과
정확히 일치**하고(단일 파일 코퍼스 16건으로 만든 작업이 13파일 자산에서 그대로
성립), **생성 스킵 0**, **인터페이스 12/12 양쪽 절반 생성**, **기본 거부 노출과
검색**, **엔드포인트 무유출**.

## 6. What was not measured / 측정하지 않은 것

Named, because a stage nobody mentions is a gap and a stage named unmeasured is
a result.

- **No foreign ORB was driven against the estate.** The servant was reached by
  our own bridge and our own generated client. `omniidl` was used as a
  *compiler* oracle, never as a peer here. The cross-ORB direction for these
  contracts is unmeasured.
- **One of twelve interfaces was served.** `ShipmentTracker`, chosen because it
  has eleven operations, an inherited attribute and two user exceptions. The
  other eleven were generated and never run. A twelve-servant process is not
  what this batch was for and `spikes/service_sweep.sh` already measures a
  multi-servant one.
- **The S1–S3 model stages never ran.** This estate is *ingested*, not
  generated: it starts as IDL, so S1/S2/S3 have no input. `sidl-infer` (S3i)
  would be the tool for proposing annotations over it and **was not run** — it
  needs a producer to measure anything, and a scripted stand-in would put a
  number where an absence belongs.
- **A constant's repository id could not be compared.** `omniidl -bpython` does
  not emit an id string for `MAX_BAYS`, so the extraction cannot see one. Ours
  emits `IDL:meridian.com/MFS/Depots/MAX_BAYS:1.0`. The row is excluded from
  both sides of the diff **by name**, so it is visible rather than silently
  counted as agreement. Whether the two compilers actually disagree here is
  unmeasured by this method.
- **The estate was written by the same author who knew the identifier-clash
  rule.** Zero case-insensitive clashes across thirteen hand-written files is a
  real result but an **indicative** one, and it is not evidence that the rule is
  easy to follow.

외국 ORB 미측정, 12개 중 1개만 서빙, S1–S3 미실행(자산은 IDL로 시작하므로 입력이
없다), `sidl-infer`는 프로듀서 없이는 아무것도 측정하지 않으므로 실행하지 않음,
상수 ID는 이 추출 방법으로 비교 불가(이름으로 제외, 합의로 계산하지 않음).
식별자 충돌 0건은 규칙을 아는 저자가 쓴 결과이므로 **참고치**다.

## 7. Reproducing / 재현

```bash
./spikes/estate/run.sh          # one section per stage
./spikes/estate/run.sh --tsv    # stage<TAB>metric<TAB>value rows only
ESTATE_KEEP=1 ./spikes/estate/run.sh   # keep the workspace for inspection
```

Needs `omniidl` (`brew install omniorb`) for stages 2 and 4. Without it both
stages report a FAILURE rather than a skip, because an unmeasured check is not a
pass.

**No machine-wide lock is taken and none is needed.** Everything lives in a
private `mktemp` directory and the one fixture is killed by a PID captured at
launch, so a concurrent `run_checks.sh` cannot collide with this and it cannot
collide with one. `run_checks.sh` was **not** edited by this batch; the group it
would take is recommended in the batch report rather than applied.

`omniidl`이 없으면 2·4단계는 건너뛰기가 아니라 **실패**로 보고한다. 머신 전역 락은
잡지 않으며 필요도 없다. `run_checks.sh`는 이 배치에서 수정하지 않았다.

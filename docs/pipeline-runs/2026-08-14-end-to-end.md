# Pipeline run — the whole path, once (2026-08-14)

Every component this exercises already existed and had been measured on its own.
Nothing had ever measured them **as one path**. This run does exactly that and
nothing else: one natural-language requirement in at the top, a live guarded
call at the bottom, and a verdict per hop between them.

The thesis under test is PLAN §1–§3 — *natural-language requirement → live ORB
binding, no hand-written stubs* — and the integration points are §7.4's I1–I4.
The deliverable is not that it works. It is the hop-by-hop evidence, the honest
hand-written-versus-generated count, and **one root cause the composition
surfaced that no component could have surfaced alone**.

Driver: `spikes/end_to_end.sh`. Footprint of the change: `spikes/` and this
file. No crate was modified.

that refuses a call, and that sentence is where it starts.

## Hand-written versus generated

Counted by the driver from the files this run produced, not asserted:

| | lines | what |
|---|---:|---|
| **hand-written, product** | **185** | requirement 1, servant 184 |
| hand-written, harness | 757 | client probe 119, agent 218, driver 371, producer 49 |
| generated by the model | 329 | brief 133, IDL 76, SIDL 120 |
| generated by the tool | 449 | stubs + skeleton 448, lib 1 |

**The honest number is 185 hand-written product lines against 778 generated,
about 4.2×.** Read it with all four of these in mind:

- **The servant body is real work and is counted as such.** 184 of the 185 lines
  are it. It is the only thing in the path a generator cannot write, because it
  is the only thing the requirement does not determine: which floors exist, what
  "already open" means, what a gate the facility cannot read reports. A ratio
  computed against a servant counted as free would be a much larger number and a
  false one.
- **Line counts are a proxy for effort and a poor one.** The 448 generated lines
  are mechanical and were written in milliseconds; the 184 hand-written ones took
  a person's attention. What the ratio actually measures is *how much of the path
  nobody had to review*, which is the claim worth making — not a productivity
  multiplier.
- **The harness is excluded from the product ratio and disclosed anyway.** 757
  lines of driver, agent and probe exist to *measure* the path, not to be it. A
  deployment ships the servant; it does not ship `agent.py`. Excluding them
  silently would have been the dishonest move, so they are in the table.
- **Comments and blank lines are counted in every bucket alike.** The servant is
  heavily commented, which inflates the hand-written side — the direction that
  makes the claim smaller, which is the right direction for it to err.

## The root cause the composition found

Per §5.1 the output of the oracle step is causes, not items. This run produced
one, and it took the whole path to make it visible.

### Cause A — the contract is not stable across runs, and everything downstream is written against a contract

`E2E_MODEL=1` re-ran S1–S3 against the same producer, the same prompts and the
same requirement file. S1, S2, S3 and S4 all passed 1/1 again. The contract was
different:

| | the run this record measures | the second run |
|---|---|---|
| module | `ParkingFacility` | `ParkingLot` |
| interface | `ParkingControl` | `GateControl` |
| operations | `get_floor_occupancy` / `get_gate_status` / `open_entry_gate` | `get_floor_availability` / `get_barrier_state` / `open_entry_barrier` |
| floor identity | `typedef long FloorLevel` (signed, basements negative) | `typedef string FloorLabel` |
| shape | one floor per call | a sequence of every floor per call |
| **the scope** | **`gate:operate`** | **`parkinglot.barrier.open`** |

Nine checks failed downstream, and all nine had this single cause:

```
hop 3 FAIL  no ParkingControlClient in the emitted module
hop 3 FAIL  no ParkingControlServant in the emitted module
hop 3 FAIL  no ParkingControlSkeleton in the emitted module
hop 3 FAIL  the servant does not compile against the generated trait
hop 4 FAIL  the dry run predicted something else: allow=0 need_scope=0 …
hop 4 FAIL  the dry run left no audit lines
hop 5 FAIL  the servant did not publish an IOR within 20s
hop 6 FAIL  no IOR to reach: the agent hop is unmeasured, which is a failure
hop 7 FAIL  no IOR to reach: the stub hop is unmeasured, which is a failure
```

This is not a defect in any stage. Every gate passed; both contracts are valid,
annotated, omniidl-clean IDL that answers the requirement. It is a property of
the **composition**, and it has three separate consequences worth stating apart:

1. **A servant is written against a contract, not against a requirement.**
   Regenerating the contract is a breaking change to every servant implementing
   it, and the pipeline has no notion of "the same contract again". A component
   test can never see this, because a component test has one contract.
2. **The exposure allowlist is written against a contract too.** The operator's
   `--expose IDL:ParkingFacility/ParkingControl:1.0` and the S5 worksheet name
   ids that a regeneration invalidates. The failure direction is at least the
   safe one — an id that no longer exists exposes nothing (`allow=0` above) —
   but an allowlist that silently covers nothing is not a good place to be
   either.
3. **The scope string drifted from the requirement's own word.** The requirement
   says `gate:operate`. One run wrote `gate:operate` into `ai_authz`; the other
   invented `parkinglot.barrier.open`. Nothing in S1's schema, S3's rules or
   S4's gate binds an identifier the requirement *states literally* to the
   annotation that enforces it. Of the three consequences this is the one with
   real teeth: a deployment whose IdP issues `gate:operate` and whose contract
   asks for `parkinglot.barrier.open` refuses every legitimate caller, and every
   gate in this project passes it.

### Cause B — one servant, two drivers, and an assertion that measured the wrong instant

The first assembly of the driver ran the mutating client probe before the
read-only agent. The agent then read `GATE_OPEN` where the contract's initial
state is closed, and failed. The fix is the **order** — the read-only caller
runs first, the mutating one last — and not a loosened assertion, because an
assertion relaxed to survive its neighbours has stopped measuring anything. One
cause, one fix, recorded because it is the shape of failure a composed harness
produces and a component harness cannot.

## What was codified

Per §5.1 a cause that is only fixed comes back; a cause that is codified cannot.
Cause B is codified in the driver itself: hop 6 runs before hop 7, with the
reason written above the hop rather than in a commit message. Cause A is
**not** codified, and deliberately so — every mechanism that would fix it is a
crate change, and this change's footprint is `spikes/` and `docs/`. The
candidates are named under *Crate changes the path needs* below so the next
change starts from a designed option rather than from this paragraph.

Two smaller things were codified along the way:

- **The producer wrapper is committed.** `2026-08-13-split-pipeline.md` recorded
  that its wrapper lived in a scratch directory and that "the recommended
  committed form is in the Harness section". It is now
  `spikes/e2e/producer.sh`, with the `${VAR:?…}` apostrophe hazard that cost
  that run a 20/20 `producer-error` batch written into its header and avoided in
  its body.
- **Replayed artifacts must carry provenance.** `spikes/e2e/recorded/` holds the
  live run's output *and* `pipeline.log`, which states the date, the producer,
  the command and the verbatim report. The driver refuses to call a replay
  measured if that file is missing — an artifact nobody can date is exactly the
  stand-in the honesty rule forbids presenting as a pipeline result.

## UNMEASURED, with reasons

Everything below was **not** measured. Each line says why, per the honesty
rules; none of them is a hop of the path this run claims.

- **S1–S3 in the same process as the rest.** The model stages ran live at
  2026-08-14 and their exact output is `spikes/e2e/recorded/`; the default
  driver mode replays those bytes and re-runs S4 and S5 over them for real. The
  model stages are therefore measured *by a recorded live run whose report is
  committed*, not by the process that printed `end-to-end: PASS`. They cannot be
  the same process while a committed servant names one contract's identifiers —
  that is Cause A, and the driver's `E2E_MODEL=1` mode exists to keep the fact
  measurable rather than to hide it.
- **Any rate.** One requirement, one run per stage. The 1/1s above are not
  percentages and no variance estimate exists.
- **Whether the contract is a *correct* reading of the requirement.** S1
  recorded ten open questions and nobody answered them; S4 gates structure, not
  intent. No human other than this document's author read the brief.
- **The generator and the evaluator are the same model family.** The producer is
  a Claude model, the gates were written by one, and this record's author is
  one. Per PLAN §8 the model-facing numbers here are **indicative**. The two
  checks in this run that were not written for it are `omniidl` (a foreign
  compiler) and `contract-check` (a peer crate with its own rules).
- **The audit log of the serving bridge.** The guard writes an audit line for
  every decision, and `orbweaver-mcp-server` prints those lines only on the
  `--dry-run` path; in serving mode they accumulate in memory and nothing emits
  them. Hop 6's refusal is visible in the *transcript* as tool content, so the
  hop is measured — but the audit trail of a live session was not, and could not
  be, from outside the process. See the findings below.
- **A foreign ORB against this contract.** `omniidl -b dump` accepted the IDL,
  which is a statement about the front end, not about the wire. No omniORB
  client was pointed at this servant; `crates/orbweaver-gen/tests/skeleton_wire.rs`
  does that for a corpus contract and nothing here re-does it for this one.
- **Anything about performance.** No timing is reported beyond the pipeline's
  wall clock, and none was measured.

The quality gate itself *was* measured, and is recorded here rather than left
implied: `cargo fmt --check` clean over the workspace, `cargo test --workspace`
**911 passed, 0 failed**. Both were run twice. The first attempt failed to
compile on `crates/orbweaver-forge/src/infer.rs`, an untracked file belonging to
concurrent work rather than to this change; the harness rule says an unmeasured
check is a failure and not a pass, so rather than reporting a subset the wait
was a sleeping, deadline-bounded loop until the tree parsed again, and then the
whole gate was run. This change modifies no crate — verified by inspection of
the working tree, where the only paths it touches are `spikes/end_to_end.sh`,
`spikes/e2e/` and this file.

## Crate changes the path needs — findings, not changes

Reported precisely and not made, per this change's footprint.

1. **`orbweaver-mcp`: the serving loop never emits the audit log.**
   `Bridge::audit()` accumulates one line per decision and
   `src/bin/orbweaver_mcp_server.rs` drains it only on the `--dry-run` branch
   (`for line in bridge.audit() { eprintln!(…) }` at the end of the dry-run
   block). In serving mode the loop over stdin never touches it, so a live
   session's ALLOW/REFUSE trail exists in memory and is discarded at exit. The
   §4.8 audit requirement is met by the *library* and not by the *process*, and
   the process is the only thing a deployment runs. The minimal change is to
   emit each new line to stderr after `session.handle_line`, which is where the
   root-handle line already goes and where a diagnostic belongs; the transport
   rule that stdout carries only protocol frames is unaffected.
2. **`orbweaver-forge`: nothing binds a literal identifier in the requirement to
   the annotation that enforces it.** Cause A(3). S1's `Brief` already has an
   `authz` field per operation and it did carry `"gate:operate"` in the run this
   record measures — so the information survives S1 and is lost between S1 and
   S3. A rule of the shape *"a token in the requirement matching
   `[a-z]+[:.][a-z]+` that S1 recorded as `authz` must appear verbatim in S3's
   `ai_authz`"* is checkable without a model, belongs in `annotate::RULES` where
   `every_rule_is_a_prompt_constraint_and_a_check` would force both halves to
   exist, and would have failed the second run.
3. **`orbweaver-forge` (larger, design first): no notion of "the same contract
   again".** Cause A(1) and A(2). Regeneration produces a valid, differently
   named contract, and every servant and allowlist downstream is bound to names.
   Options, none of them free: pin module/interface/operation names in the brief
   and make S2's gate enforce them; or diff a regenerated contract against the
   registered one through `orbweaver-registry`'s §5.3 differ and refuse a
   rename that is not declared as an evolution. The second reuses machinery that
   exists. Neither should be built from this paragraph without a decision
   document, since it changes what S2 is allowed to choose.
4. **`orbweaver-gen`: constants are emitted as a skip.**
   `gen-corpus` reported `skipped IDL:ParkingFacility/GATE_OPERATE_PERMISSION:1.0:
   constants are not generated yet`. The contract declared the scope name as a
   `const string` precisely so a servant could refer to it, and a servant cannot.
   Minor, already known, and stated here because this run is where the omission
   had a visible consequence rather than a theoretical one.

None of these blocked the path. Every hop was measured with the crates exactly
as they are.

## Reproducing

```sh
./spikes/end_to_end.sh                  # replay the recorded contract, ~2 min
E2E_MODEL=1 ./spikes/end_to_end.sh      # call the producer again (see Cause A)
E2E_KEEP=1 ./spikes/end_to_end.sh       # keep the scratch workspace
```

The driver takes **no** harness lock. `run_checks.sh` needs one because it kills
fixtures by pattern and writes fixed `/tmp` log paths; everything here lives in
a private `mktemp` directory and its one fixture is killed by captured PID, so
it can neither collide with a concurrent harness nor be collided with.

## Harness — recommended, not applied

`run_checks.sh` was outside this change's footprint, so nothing below was added
to it. The replay mode needs no model and no network and belongs in the gate;
the model mode does not, for the same reason the 2026-08-13 record gave (a model
call and an API key do not belong in a gate).

```sh
# The whole path, replayed: S4/S5 for real over a recorded contract, both
# generated halves compiled and driven, the guard refusing a scope on the wire.
# ~2 min, no model, no network beyond loopback. Skipping is a FAILURE.
hr "end-to-end — requirement → contract → both halves → guarded call"
if [ -x "$ROOT/spikes/end_to_end.sh" ]; then
    e2e=$("$ROOT/spikes/end_to_end.sh" 2>&1)
    case "$e2e" in
        *"end-to-end: PASS"*) pass "end-to-end path" ;;
        *) fail "end-to-end path: $(printf '%s' "$e2e" | grep -c 'FAIL') check(s)"
           printf '%s\n' "$e2e" | grep 'FAIL' ;;
    esac
else
    fail "spikes/end_to_end.sh missing — an unmeasured path is a failure"
fi
```

Two cautions for whoever applies it. It builds a crate **outside** the workspace
(`gen-corpus`'s output has its own `[workspace]` and its own `target/`), so a
cold run pays a full dependency build; budget for it or prime the cache.
And it binds a loopback port, so it belongs after the lock is taken even though
it does not need the lock's other guarantees.

## 요약 (Korean summary of the findings)

이 기록은 영어가 정본이다. 프로젝트 규약상 문서는 한국어와 구조적으로 대칭이어야
하지만 `docs/pipeline-runs/`의 선례는 영문 단독이므로, 여기서는 **결론만** 옮긴다.

- **경로 전체를 한 번에 측정했다.** 자연어 요구사항 한 건 → S1–S5 → 생성된 양쪽
  절반(클라이언트 스텁·서버 스켈레톤) → 우리 POA 위의 서번트 → MCP 브릿지의 가드
  → 실제 호출. 8개 홉 전부 측정, `end-to-end: PASS`.
- **가드가 실제로 거부했다.** 요구사항 문장에 적힌 `gate:operate` 권한이 S1의
  `authz` → S3의 `ai_authz` → `authz.scopes` 단계를 거쳐, 스코프를 갖지 않은
  호출자의 `open_entry_gate` 호출을 거부하는 것으로 나타났다. 드라이런이 그
  거부를 **호출 전에** 정확히 예측했다.
- **손으로 쓴 줄 185, 생성된 줄 778 (약 4.2배).** 서번트 본문 184줄은 실제 작업
  이며 공짜로 계산하지 않았다. 하네스 757줄은 제품이 아니므로 비율에서 제외하되
  표에 공개한다.
- **근본원인 A — 계약은 실행마다 달라진다.** 같은 요구사항·같은 프롬프트로 다시
  돌리면 모든 게이트를 통과하는 **다른** 계약이 나온다(`ParkingLot::GateControl`).
  하위 9개 검사가 전부 이 하나의 원인으로 실패했다. 특히 요구사항이 문자 그대로
  적은 `gate:operate`가 두 번째 실행에서는 `parkinglot.barrier.open`으로 바뀌었다
  — IdP가 발급하는 스코프와 계약이 요구하는 스코프가 어긋나면 정당한 호출자가
  전부 거부되며, 현재 어떤 게이트도 이를 잡지 못한다.
- **근본원인 B — 서번트 하나에 드라이버 둘.** 읽기 전용 호출자를 상태를 바꾸는
  호출자보다 먼저 돌려야 한다. 단언을 느슨하게 고치지 않고 **순서**로 고쳤다.
- **크레이트는 하나도 수정하지 않았다.** 필요한 변경은 *발견*으로만 기록했다:
  서빙 중 감사 로그 미출력(`orbweaver-mcp`), 요구사항 토큰과 `ai_authz`의 결속
  부재(`orbweaver-forge`), 재생성 시 이름 안정성 부재, 상수 미생성
  (`orbweaver-gen`).
